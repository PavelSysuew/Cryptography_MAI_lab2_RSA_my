## Сборка и запуск

Все настройки сборки описаны в `CMakePresets.json`. Имя пресета задаёт и тип сборки, и папку, куда она попадёт.

```bash
cmake --preset debug          # 1. конфигурация: читает CMakeLists.txt, создаёт build/debug
cmake --build --preset debug  # 2. сборка: компилирует изменённые файлы
./build/debug/RSA             # 3. запуск
ctest --preset debug          # 4. автоматические тесты
```

- Шаг 1 нужен один раз, а потом только после изменения `CMakeLists.txt` или `CMakePresets.json`. Если менялись только `.cpp` или `.hpp`, достаточно шагов 2 и 3.
- Вместо `debug` можно подставить `release` или `asan` (см. таблицу ниже). Программа появится в `build/<пресет>/RSA`.

### Шифрование настоящих файлов

Для файлового режима на Linux нужны заголовки OpenSSL 3 (пакет `libssl-dev` в Debian/Ubuntu).

Запустите `./build/release/RSA` из каталога проекта. Пункт **3** запрашивает путь к исходному файлу и сохраняет рядом копию с расширением `.rsaenc`. Пункт **4** принимает путь к этой копии и восстанавливает исходное расширение. Если имя занято, программа добавит номер, например `Фото (2).jpg`. После операции программа показывает полный путь к результату и возвращает в главное меню.

При первом шифровании меню создаёт пару в `.rsa-keys/` текущего каталога. Для работы по одному пути новый закрытый ключ хранится без пароля с правами `0600`. Сохраните его резервную копию. Если вы уже создали пару командой `file-keygen` в этом каталоге, меню использует её, а при расшифровании запрашивает заданный ранее пароль.

Те же операции доступны из командной строки с явным указанием ключей и имён файлов.

```bash
cmake --preset release
cmake --build --preset release
mkdir -p -m 700 .rsa-keys

# Один раз создайте пару ключей. Программа запросит пароль для закрытого ключа.
./build/release/RSA file-keygen .rsa-keys/private.pem .rsa-keys/public.pem

# Зашифруйте файл открытым ключом.
./build/release/RSA file-encrypt .rsa-keys/public.pem "архив.tar" "архив.tar.rsaenc"

# В другом запуске восстановите файл закрытым ключом и его паролем.
./build/release/RSA file-decrypt .rsa-keys/private.pem "архив.tar.rsaenc" "архив-восстановленный.tar"
cmp -- "архив.tar" "архив-восстановленный.tar"
```

Один открытый ключ подходит для нескольких файлов. Для восстановления нужна соответствующая копия закрытого ключа и его пароль. Храните резервную копию ключа отдельно, а для шифрования файлов другому человеку используйте его открытый ключ.

Режим поддерживает произвольные бинарные файлы до 1 ТиБ и читает их блоками по 1 МиБ. Для каждого файла OpenSSL генерирует отдельный ключ AES-256-GCM и шифрует его с помощью RSA-OAEP с SHA-256. Формат `.rsaenc` используется этой программой.

Операции создают новый файл, оставляя исходник на месте. Путь назначения должен быть свободен, а его каталог — поддерживать жёсткие ссылки. Расшифрованный результат публикуется после проверки всех тегов и конца файла. При аварийном завершении процесса в каталоге назначения может остаться временный файл `.rsa-file.*` с правами `0600`.

Для сборки только учебного меню без OpenSSL используйте `cmake --preset debug -DLAB_FILE_CRYPTO=OFF`.

### Пресеты

| Пресет | Флаги компилятора | Когда использовать |
|---|---|---|
| `debug` | `-g`, без оптимизации | пишу код, отлаживаю по шагам, смотрю переменные |
| `release` | `-O3 -DNDEBUG` | генерация больших ключей, замеры скорости, демонстрация. **`assert` отключены!** |
| `asan` | `-g -fsanitize=address,undefined` | поиск скрытых ошибок: выход за границы, утечки, переполнение `int`, деление на ноль. Работает в 2–3 раза медленнее |

### Полезные команды

```bash
cmake --list-presets                          # список пресетов
cmake --build --preset debug --clean-first    # пересобрать всё с нуля
cmake --preset debug -DLAB_SANITIZE=ON        # включить/выключить option вручную
rm -rf build                                  # удалить все сборки (если сломался кэш CMake)
```

Сообщения `message(STATUS ...)` из `CMakeLists.txt` (компилятор, версия Boost, тип сборки, список файлов) печатаются на шаге 1.

### Цели CMake

| Цель | Тип | Что это |
|---|---|---|
| `lab2_core` | статическая библиотека | весь код заданий 1–4 (`src/` + `include/`) |
| `RSA` | исполняемый файл | демонстрация, `main.cpp`, подключает `lab2_core` |
| `lab2_options` | INTERFACE | общие настройки: C++20, предупреждения, санитайзеры |

### Как добавить новый файл

1. Заголовок кладу в `include/имя.hpp` (первой строкой `#pragma once`), реализацию — в `src/имя.cpp`.
2. Добавляю `src/имя.cpp` в список `LAB2_SOURCES` в `CMakeLists.txt`. Файлы перечислены явно, сами они не подхватываются.
3. В коде подключаю `#include "имя.hpp"`. Путь к `include/` уже настроен.
4. Пересобираю: `cmake --build --preset debug` (CMake сам перезапустит конфигурацию, раз изменился `CMakeLists.txt`).
