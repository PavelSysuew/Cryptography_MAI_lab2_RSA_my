## Сборка и запуск

Для пресета `debug` нужны CMake 3.25 или новее, Ninja, компилятор с поддержкой C++20 и заголовки Boost. Команды выполняются из корня проекта.

```bash
cmake --preset debug
cmake --build --preset debug --target RSA
./build/debug/RSA
```

Пункт `1` главного меню открывает математические функции. Пункт `2` открывает тесты простоты. Пункт `5` завершает программу.

При надёжности `0.99` верхняя граница вероятности ошибочного прохождения теста составным числом равна `0.01`. Если оценка для теста Ферма требует больше 1 000 000 итераций, программа сообщает об ошибке.

### Проверка ключей RSA

Пункт `4` главного меню открывает проверку ключей. В нём пункт `1` создаёт учебную пару через обычный генератор RSA с тестом Миллера — Рабина и 16-битными множителями. Пункт `2` загружает пару из файла `.rsa`. В обоих случаях программа проверяет нижнюю границу `d > 2^(L/2)`, где `L` — битовая длина модуля `n`, и выводит только результат сравнения. Используется нижняя граница из § 6.2.1 [NIST SP 800-56B Rev. 2](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-56Br2.pdf) для учебного примера.

### Демонстрация RSA

Открой пункт `3` главного меню, затем выбери `1` для генерации ключей. Выбери тест Миллера — Рабина, надёжность `0.99` и битовую длину `16`. Затем пунктом `2` запусти шифрование и расшифрование числа `42`. После расшифрования программа должна вывести `42`. Для работы с сохранённой парой сразу выбери `6` и загрузи файл ключей.

Учебная версия принимает целые сообщения из диапазона `[0, n)` и битовую длину каждого множителя от 10 бит. При длине множителей `L` генератор требует, чтобы методу Ферма понадобилось не меньше `2^(L / 2)` шагов с округлением `L / 2` вниз. При малых учебных размерах это число остаётся небольшим. Выбор теста Ферма для генерации ключей подчиняется указанному выше пределу итераций.

### Работа с файлами

В подменю RSA пункты `3` и `4` шифруют и расшифровывают файлы. При шифровании нажми Enter в поле пути для результата, чтобы создать файл рядом с исходным. Например, для `report.txt` программа предложит `report_encrypted.txt`. Можно ввести свой путь. При расшифровании укажи свободный путь для результата. Для расшифрования после перезапуска сохрани ключи пунктом `5` и загрузи их пунктом `6`.

При сохранении и загрузке ключей Enter выбирает `keys/rsa_keys.rsa`. Имя без пути, например `my_keys.rsa`, тоже относится к папке `keys` в каталоге запуска. При первом сохранении программа создаёт папку. Другую папку можно указать явно.

Этот режим демонстрирует RSA на небольших двоичных файлах. Блоки шифруются напрямую и формат не проверяет их подлинность. Файл ключей содержит закрытую экспоненту в открытом виде и создаётся с правами чтения и записи для владельца.

### Тесты

```bash
cmake --build --preset debug --target test_1_RSA test_2_RSA test_3_RSA
ctest --preset debug
```

- `ctest --preset debug -N` — показать список тестов без запуска.
- `ctest --preset debug -V` — запустить тесты и показать вывод всех проверок.
- `./build/debug/test_1_RSA` — запустить проверки математических функций напрямую.
- `./build/debug/test_2_RSA` — запустить проверки тестов простоты напрямую.
- `./build/debug/test_3_RSA` — запустить проверки генерации ключей, шифрования и расшифрования.

После правок в `.cpp` и `.hpp` достаточно повторить сборку нужной цели. Если проект перенесли и CMake сообщает о старом пути в кэше, выполни `cmake --fresh --preset debug`.
